# react-semantic-images

Place images on a website using natural-language descriptions instead of hardcoded file paths.
A local CLIP model (running 100% in Node via ONNX / Transformers.js) maps each description to
an unassigned image from a pool during a pre-compile build step. No API keys. No Python.
No cloud.

```tsx
<SemanticImage description="a sunny mountain hike at golden hour" width={800} height={600} />
```

```bash
npx match-images
# writes public/semantic-manifest.json
```

---

## Install

```bash
npm install react-semantic-images
```

## Project layout

```
your-project/
├── public/
│   ├── semantic-pool/        ← drop unassigned JPG / PNG / WebP / AVIF here
│   └── semantic-manifest.json ← generated by `npx match-images`
└── src/ (or app/, pages/, components/)
    └── ... your <SemanticImage /> usages
```

## Component

```tsx
import { SemanticImage } from "react-semantic-images";

export function Hero() {
  return (
    <SemanticImage
      description="a sunny mountain hike at golden hour"
      alt="Mountain hike"
      width={1200}
      height={800}
    />
  );
}
```

### Props

| Prop          | Type                | Default                          | Description |
|---------------|---------------------|----------------------------------|-------------|
| `description` | `string` *required* | —                                | What the image should depict. Looked up in the manifest at runtime. |
| `lock`        | `boolean`           | `false`                          | If `true`, the CLI will never reassign a different image to this description on future runs. |
| `as`          | `ReactElement`      | `"img"`                          | Render with a custom component (e.g. Next.js `next/image`). |
| `manifestUrl` | `string`            | `"/semantic-manifest.json"`      | Override where the manifest is fetched from. |
| `fallbackSrc` | `string`            | inline SVG placeholder           | Render this src when no match is found. |
| ...           | All standard `<img>` props are forwarded.        |             |

### Using with `next/image`

```tsx
import Image from "next/image";
import { SemanticImage } from "react-semantic-images";

<SemanticImage as={Image} description="cozy coffee shop interior" width={800} height={600} />;
```

### Custom wrapper components

You almost certainly don't want to sprinkle `as={Image}` and shared defaults all over every
page. The recommended pattern is to wrap `SemanticImage` once in your own component and use
that wrapper everywhere:

```tsx
// components/SemanticImg.tsx
import NextImage from "next/image";
import { SemanticImage, type SemanticImageProps } from "react-semantic-images";

type SemanticImgProps = Omit<SemanticImageProps, "as"> & { className?: string };

export function SemanticImg({ description, lock, ...rest }: SemanticImgProps) {
  return (
    <SemanticImage
      as={NextImage as React.ElementType}
      description={description}
      lock={lock}
      {...(rest as React.ImgHTMLAttributes<HTMLImageElement>)}
    />
  );
}
```

Then use `<SemanticImg>` across every page — no imports of `SemanticImage` or `next/image`
needed anywhere else:

```tsx
// app/page.tsx
import { SemanticImg } from "@/components/SemanticImg";

export default function HomePage() {
  return (
    <main>
      <SemanticImg description="hero shot of a mountain at sunrise" width={1200} height={600} />
      <SemanticImg description="team photo in open-plan office" lock width={800} height={400} />
    </main>
  );
}
```

The CLI automatically discovers wrapper components — you never have to register them anywhere.
It works by detecting that `SemanticImg` renders `<SemanticImage description={description} …>`,
marking it as a semantic image component, and then scanning every file for literal `description`
props on `<SemanticImg>` exactly as it would for `<SemanticImage>`.

This works transitively: if you wrap your wrapper (e.g. `HeroImg` wraps `SemanticImg`), the
CLI will discover the full chain and correctly collect descriptions from `<HeroImg>` usages too.

The `lock` prop behaves identically on any wrapper — place it at the call site:

```tsx
<SemanticImg description="company founder portrait" lock />
```

### Runtime behavior

1. The component fetches `/semantic-manifest.json` once per page load (cached at the module level).
2. It also checks `window.__SEMANTIC_MANIFEST__` for SSR-injected manifests, useful for Next.js
   apps that want to inline the manifest in `layout.tsx`.
3. If the manifest does not exist or the description is missing, an inline SVG placeholder is
   rendered. The component never throws.

## CLI: `npx match-images`

Run from your project root any time you add / change a `<SemanticImage />` or update the pool:

```bash
npx match-images
```

### Options

| Flag         | Default                                                  |
|--------------|----------------------------------------------------------|
| `--pool`     | `public/semantic-pool`                                   |
| `--out`      | `public/semantic-manifest.json`                          |
| `--public`   | `public`                                                 |
| `--src`      | `src/**`, `app/**`, `pages/**`, `components/**` (repeatable)|
| `--cache`    | `node_modules/.cache/react-semantic-images/embeddings.json` |

### Pipeline

1. **Scan source code** using Babel's JSX parser. First discovers any wrapper components that
   forward `description` through to `<SemanticImage>` (or to another wrapper), then collects
   every literal `description` prop from `<SemanticImage>` and all discovered wrappers alike.
   Wrapper discovery is automatic and transitive — no registration required.
2. **Read the existing manifest** so that any locked description with an existing mapping is preserved.
3. **Embed images** with `Xenova/clip-vit-base-patch16` (quantized ONNX). MD5-hashed cache means
   unchanged images skip the model on subsequent runs.
4. **Embed text** for every unlocked description.
5. **Cosine-similarity matrix + greedy stable assignment** so each description gets a unique image.
6. **Warn** if a best match scores below `0.2` (the description likely has no good asset).
7. **Write the manifest** as `{ "description": "/semantic-pool/file.jpg" }`.

### Lock behavior

```tsx
<SemanticImage description="company founder portrait" lock />
```

The CLI will refuse to ever reassign this description to a different file as long as its
existing mapping still points at a file present in the pool. The image is also removed from the
candidate pool, so other descriptions cannot steal it.

## Framework compatibility

The manifest is served from the public root as a plain static JSON file, so every modern React
framework can load it natively:

* **Next.js** (App Router and Pages Router)
* **Vite** (React, Remix-style)
* **Remix**
* **Create React App**
* **Astro** with React islands

No bundler config, no special loader.
